# Frontend upgrade: итог текущего этапа

## Главная проблема

В picker выбранный слот было легко пропустить: состояние зависело от тёмной
заливки, тени и масштабирования. Масштабирование также могло визуально
перекрывать соседние кнопки и менять ощущение сетки.

## Реализованное решение

`Appointment24hPicker` использует стабильное состояние выбора:

- тёмно-синяя заливка и белый текст;
- контрастная рамка и внешний `outline`;
- галочка рядом с выбранным значением;
- `aria-pressed="true"`;
- без `scale` и без конкурирующего `box-shadow` ring.

Такое состояние сохраняет геометрию сетки и работает одинаково для даты и
быстрых временных слотов.

## Дополнительные точечные изменения

- Удалены неиспользуемые `useState`, `Sparkles`, `moscowNow` и связанный импорт.
- Глобальные самописные `.ring-1`, `.ring-2`, `.scale-105`, `.scale-110` и
  неиспользуемые декоративные utility-блоки удалены из `product.css`.
- Административные вкладки сообщают активную страницу через `aria-current`.
- Для новых transition-правил picker добавлен reduced-motion fallback.

## Реальный охват сценариев

Изменение не переписывает operator/admin/API-слои. Они уже используют рабочие
компоненты и API-методы проекта; для них исправлена только семантика активной
административной вкладки. Отдельная визуальная переработка этих экранов не
считается выполненной.
